============================================================================
 6. CASCADE MASK R-CNN  (the right half of the paper table)
============================================================================
 mmdet 3.x ships Swin configs for Mask R-CNN but NOT for Cascade Mask R-CNN.
 Those checkpoints only exist in Microsoft's Swin-Transformer-Object-Detection
 repo, in mmdet 2.x format, so they need a one-time conversion. The mmdet 3.x
 model configs are provided here:

   ./configs/det/cascade-mask-rcnn_swin-t-p4-w7_fpn_ms-crop-3x_coco.py
   ./configs/det/cascade-mask-rcnn_swin-s-p4-w7_fpn_ms-crop-3x_coco.py

 --- 6a. Download the mmdet 2.x checkpoints -------------------------------
 From the Swin-Transformer-Object-Detection MODEL ZOO (github.com/
 SwinTransformer/Swin-Transformer-Object-Detection), grab the 3x
 Cascade Mask R-CNN rows:

   cascade_mask_rcnn_swin_tiny_patch4_window7.pth     (published 50.4 / 43.7)
   cascade_mask_rcnn_swin_small_patch4_window7.pth    (published 51.9 / 45.0)

 Put both in ./checkpoints/det/.

 --- 6b. Convert them to mmdet 3.x ----------------------------------------
 The backbone needs more than renaming: mmdet's PatchMerging uses nn.Unfold,
 which orders the four sub-patches differently from the original Swin's
 slicing, so the reduction/norm weights must be permuted. The converter calls
 mmdet's own swin_converter for that, then verifies the key sets against the
 target config.

python tools/convert_swin_det_ckpt.py --src ./checkpoints/det/cascade_mask_rcnn_swin_tiny_patch4_window7.pth --dst ./checkpoints/det/cascade_mask_rcnn_swin_t_3x_mmdet3.pth --config ./configs/det/cascade-mask-rcnn_swin-t-p4-w7_fpn_ms-crop-3x_coco.py

python tools/convert_swin_det_ckpt.py --src ./checkpoints/det/cascade_mask_rcnn_swin_small_patch4_window7.pth --dst ./checkpoints/det/cascade_mask_rcnn_swin_s_3x_mmdet3.pth --config ./configs/det/cascade-mask-rcnn_swin-s-p4-w7_fpn_ms-crop-3x_coco.py

 Expect "key sets match". If it reports missing keys or shape mismatches, the
 conversion is wrong -- stop, do not run the experiments on it.

 --- 6c. VERIFY the conversion before anything else -----------------------
 The key-set check is necessary but not sufficient. The real proof is
 reproducing the published FP32 number. Run this FIRST:

python run_mixed_precision_det.py --model cascade_mask_rcnn_swin_t_3x --checkpoint ./checkpoints/det/cascade_mask_rcnn_swin_t_3x_mmdet3.pth --data-root D:/COCO/coco2017 --eval-fp-only

 Must print approximately 50.4 box / 43.7 mask. If it prints something far
 off (e.g. 5 or 30), the conversion or the config is wrong and every
 quantized number built on it would be meaningless.
